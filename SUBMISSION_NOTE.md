# FollowUp — submission note

I built a lead follow-up desk for a packaging-equipment sales team using Python, Streamlit, and SQLite. It includes 25 fictional leads assigned to five reps and 25 WhatsApp-style conversations. Reps see overdue and today's follow-ups first, open a lead's conversation and recommendation, edit and save a draft, and record it as sent. Adding a lead or chat triggers an updated recommendation. SQLite keeps the history and edits across restarts, without spreadsheet credentials or a separate database server.

The agent produces a Hot/Warm/Cold tag, one-line reason, follow-up date, and message draft. Its local baseline prioritizes the latest buyer intent: quote, demo, or order requests are Hot; active enquiries and budget/timing delays are Warm; stale enquiries without stronger intent are Cold. Explicit refusals pause outreach. Requested dates override default intervals, and past dates remain overdue. Recording a sent message logs the actual edited text and schedules the next check-in. The optional OpenAI mode reads the conversation and returns a validated structured decision; failed calls fall back visibly to local rules. The default no-key mode is deterministic automation rather than an LLM, and its simple English rules have limitations.

I used OpenAI Codex to assist with implementation, sample data, and tests. The optional runtime AI integration uses the OpenAI Responses API; a live model request was attempted, but exhausted API credits prevented successful inference. This still needs verification after credits are available. Automated checks cover classification, requested dates, persistence, sent-message logging, opt-outs, stale edits, fallback, and the Streamlit screen. Next I would evaluate recommendations against rep-labelled conversations, improve multilingual intent and scheduling, and move to managed Postgres if deployment needs multiple instances. Login, actual WhatsApp sending, and payments were kept out of scope.
